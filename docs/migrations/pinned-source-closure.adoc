= Pinned reusable source closure: implementation and evidence
:revdate: 2026-11-07

The local implementation verifies reviewed direct reusable-workflow edges
against exact Git source objects and joins their reviewed dependency records
to the ordinary vendor lock for closure auditing. Local acceptance checks pass;
hosted results are recorded in Fleet draft #652. This records work based on
`48de76a5bcf466f46e4e973a21ca911ebec1b23c`, with main/base
`34908580b98cd354caa3bfc5a000bc7935957fce`. It does not certify the entire fleet
or declare the secret-scanner migration ready.

== Vendor lock and source-attested records

Official `gh-actions-lock` v0.4.1 excludes cross-repository `jobs.<id>.uses`
from locking. The supported v0.0.3 vendor lock retains all 20 ordinary records
unchanged. The source manifest separately preserves the ten original records
removed by that migration: two reusable parent records and eight action records,
including their original ref, commit, owner/repository IDs and nested edges.
The verifier derives one additional EA governance parent, yielding 11
source-attested records in the integrated audit. The vendor lock itself is not
rewritten to pretend that the official tool locks these external reusables.

`scripts/lib/pinned-reusable-sources.json` binds each active caller/job to an
exact repository, full commit, workflow path, Git blob and direct `uses` set.
Two old workflows remain explicitly labelled `retained-review`. The manifest's
reviewed inventory SHA-256 is
`63ffe6145c51bf5c44ac5f7d2ae9f304feb4acf7e9e3b52c6891e752ba126046`.
No dependency SHA or caller pin is changed by this closure integration.

== Object verification and evidence boundary

`scripts/audit-pinned-reusable-sources.sh` fetches only when explicitly invoked
with `--fetch-sources`. It reads published sources over HTTPS into a separate
bare Git cache. Fetched code is never checked out or executed. Git configuration,
replacement refs, source-rewriting settings and source-path file modes are
checked within the verifier's supported profile.

The verifier hashes the raw commit object, reads its tree identity, verifies
each tree component, and requires the manifest's regular-file blob at the exact
path. It hashes that blob's raw Git object content before parsing direct edges.
It independently discovers active caller/job/path/commit bindings in the local
workflows and compares them with the manifest. Receipt unions, dependency
identities, overlaps and graph targets must also agree before any supplemental
record is exported to the integrated audit.

Absent cached objects produce nonzero `NOT-RUN`; corrupt or mismatched objects
produce findings. Duplicate JSON keys, malformed dependency identities and
ambiguous vendor fields fail closed. Unsupported YAML aliases, merges, flow
forms, dynamic/local references or nested reusable calls cannot establish a
source proof. Evidence unavailable to the parser is reported without a fabricated
pass. An unsuccessful evidence pass exports no source attestation.

The reviewed bound is the direct `uses` sets of the named reusable workflows
plus the existing composite-action receipts and dependency graph. It does not
establish arbitrary recursive provenance of invoked scripts, runtime downloads,
container images or program dependencies. Collected metadata confirms the
existing upload-pages composite's upload-artifact edge; the Rust toolchain
composite has no nested `uses`.

The source job runs helper fixtures, explicit source fetching, the preserved
closure controls, the integrated offline audit, preflight entrypoint controls
and the prepared-migration preflight. Its cache is available to the proposed-tree
preflight, which snapshots both the helper and manifest. A missing vendor parent
is accepted only through successful integrated source verification; manifest
presence alone is not proof. Existing secret, trigger, context and canary
requirements remain enforced. Missing canary evidence still makes standalone
preflight exit 2, so migration readiness is not asserted.

The E2E job declares `needs: pinned-source-closure`, uses `always()`, and begins
with a guard requiring that dependency's result to equal `success`. Failure,
not-run, cancellation or skipping cannot quietly satisfy that guard. This is
E2E dependency coupling. The live branch rules did not require the E2E context
at the last observation; no branch-ruleset requirement or ruleset change is
claimed.

Reproduce from the repository root, with a separate source cache:

[source,bash]
----
export PINNED_SOURCE_CACHE=/absolute/path/to/source-cache
bash scripts/audit-pinned-reusable-sources.sh --fetch-sources --json
bash scripts/audit-pinned-reusable-sources.sh --json
bash scripts/tests/pinned-reusable-sources-test.sh
bash scripts/tests/lock-closure-test.sh
bash scripts/tests/pinned-source-entrypoints-test.sh
cargo test --locked --manifest-path tools/workflow-lock-audit/Cargo.toml
bash scripts/audit-lock-closure.sh --json
----

The helper defaults to the tracked manifest. It also accepts explicit
`--manifest`, `--repo-root`, `--lock`, `--receipts` and `--cache` paths. The first
helper invocation fetches; the second uses cached objects offline. These checks
inspect source data and fixtures, not fetched executable code.

== Remaining observations

Local Debian `en_GB.UTF-8` report-back runs have three ordering failures on both
the base and candidate; this closure change does not claim to repair them or to
make the full repository E2E suite pass. Nine governance findings remained at the
last observation. The latest hosted outcomes are recorded in draft PR #652;
local acceptance is not a claim that every hosted repository check is green.

No normative policy, standards draft 1419, fleet draft 651, ruleset, mirror or
credential is changed by this closure integration. Source caches and raw local
logs are local-only evidence. The tracked manifest and receipt rows carry the
reviewable identities; local absolute paths are not presented as downloadable
GitHub artifacts.
