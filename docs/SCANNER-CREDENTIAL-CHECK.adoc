= Check the saved scanner credential
:revdate: 2026-11-16

Run the manual `Hypatia Security Scan` workflow with
`credential_read_check` selected to validate this repository's
`HYPATIA_SCAN_PAT` secret. This mode skips the normal scanner and calls
Hypatia's pinned credential checker with only that secret. It has a separate
concurrency group, so a check does not cancel an ordinary scan of the same ref.
Push, pull-request, scheduled and default manual runs retain the normal scan.

The checker authenticates, then reads at most one alert from each of
`hyperpolymath/hypatia`'s Dependabot, code-scanning and secret-scanning
endpoints. Hypatia is a fixed probe target with all three endpoints enabled.
The value comes from this caller's secret store. Passing proves this saved
value can authenticate and read those three endpoints; it does not prove
fleet's own endpoint availability, estate-wide coverage, absence of alerts
or write access. A failed or unavailable endpoint fails the check.

The check does not check out source, execute scanners, publish findings or
send dispatches. API response bodies are suppressed; secret scanning also
requests `hide_secret=true`. The callee's dispatch job is skipped, and no
dispatch secret is passed. Never use `secrets: inherit` for this check.

For the estate scanner, the intended fine-grained token grants Contents,
Dependabot alerts, Code scanning alerts and Secret scanning alerts read-only
under resource owner `hyperpolymath`; Metadata read is automatic. Selecting
all repositories covers that owner's repositories, not another owner's
security data. A token's display name does not update an Actions secret:
replacement values must be installed in each intended secret store.

The caller is also recorded in `scripts/lib/pinned-reusable-sources.json`,
with Git blob `15c597ea720a5affb861dab058084f7245ee4cbd` and content SHA-256
`645e8ac8ff118c33f2dc941ec46f1abac895f7836339736841c269e4b9dc084d` for the
pinned checker. Its direct dependency receipt is emitted from those source
bytes using `audit-lock-closure.sh --emit-receipt`. Fleet's source verifier
authenticates that source and its edge to harden-runner; the ordinary vendor
lock remains unchanged because this adds a remote job-level reusable call.

Live validation on 16 November: run `43836851465` passed the scanner job
using fleet's saved credential. The normal scan and dispatch jobs were
skipped. This is the bounded credential-read receipt described above.
